veil, end to end as a GitHub Action

One workflow run handles one repo. It reads the open Gozu Tickets, makes Fixes in a private clone, opens Fix PRs for a person to review, and writes a report. Nothing here merges.

1. The whole run: who talks to whom

Read it from top to bottom. Time moves down. The dashed box repeats once for each group. The Engine is the only part that talks to Jira, GitHub and OpenAI. The Shell only prepares it and reports.

2. The gates before the Engine starts

Every check that needs no credential comes first. A failure prints one redacted error line, exits 1 and changes no ticket. A trigger that is turned off is not a failure. It exits 0 with a notice. The default is: workflow_dispatch on, schedule off. A pull_request event never runs.

3. Which tickets the Engine may fix

The Jira search is wide. The Engine then removes tickets until only safe ones remain. This is why a second run does not repeat work: an open Fix PR or a failed-fix label removes the ticket.

4. Grouping

A group is one checkout and one Fix PR. High tickets run first. The branch is named after the first Fix that passed, not after the first ticket.

5. One ticket: two attempts at most

The cheap model tries first. If it fails, the Engine drops its edits and the strong model tries once. The second attempt sees only the redacted reason of the first failure.

6. Inside one attempt

The model works in a loop. It reads files and edits through five tools. It ends with finish. The Engine checks the finish text and the change before it accepts a Fix.

7. What every edit must pass

These are rules in code, not settings. A refusal goes back to the model as text. The model can try another edit.

8. After the fixing: PRs, Jira and the report

One PR opens for each group, ready for review. veil never merges and never moves a ticket to Done. The run report is redacted before it is written.
