The veil GitHub Action

One workflow run handles one repo. It runs the Engine once and writes a report. A failure before the Engine starts changes no ticket.

1. What starts a run

scheduleOff by default. Turn on schedule_enabled.
workflow_dispatchA person starts it by hand. On by default.
repository_dispatchAn outside system starts it, for example a Jira Automation rule.
Any other eventFor example pull_request. The run fails. A fork must never get secrets.
↓

2. The workflow job on the GitHub runner

Concurrency groupOne run for each repo. A new event waits. It does not cancel the run.
Check out the repopersist-credentials: false. The Action reads .gozu/jira-to-pr.yml from this checkout.
Run the veil imageThe image is built before. Nothing installs at run time.
  • Permissions: contents: write and pull-requests: write. No other permission.
  • Secrets go in through env: GITHUB_TOKEN, JIRA_EMAIL, JIRA_API_TOKEN, OPENAI_API_KEY.
↓

3. Inside the container: run_action

Read the runnerRepo, workspace, event, summary file.
Load settingsThe repo file is the only layer. A wrong value stops the run.
Check the eventA trigger that is off ends the run with a notice and exit 0.
Read credentialsA missing or short value stops the run. The message names the variable.
Mask the secrets::add-mask:: for each credential, line by line.
Build the contextJira tracker for this repo only. GitHub repo provider. OpenAI model client.
↓
Run the Engine onceSee the other diagram. The Engine fixes the eligible tickets and opens draft PRs.
Close the checkoutsAlways, also after an error.
Write the reportFix PRs, the outcome of each ticket, skipped tickets and tokens used go to the step summary.
↓

Result: exit 0

On GitHubDraft Fix PR into the Source PR branch.
In JiraComment with the PR link. Ticket moved to review.
  • A Failed Fix is a normal result, not an error. The ticket gets a comment and a marker label.

Result: exit 1

One error line::error:: with the credential values hidden.
No ticket changedBefore the Engine starts, nothing is touched.
  • An expired token stops the repo in the middle of a run. The tickets stay for the next run. The report says token_expired.
