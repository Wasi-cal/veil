How veil works

veil reads open Gozu Tickets and fixes the flagged code. It opens a draft Fix PR for a person to review. It never merges.

What veil reads

1. ScannerGozurion or the Gozu CLI scans the code with Semgrep, Trivy or SonarQube.
↓
2. Gozu Ticket in JiraThe ticket names the repository, file, line, severity and the exact branch. It has an issue- label.
3. Source PRA developer opened this PR. It must be open. veil fixes code on its branch.
4. SettingsThe file .gozu/jira-to-pr.yml in the repo.

What the Engine does in one run

1Find the ticketsJira search: open, no assignee, and the eligible label if one is set.
2Skip what it must not touchFix branch, Failed Fix, no issue- label, duplicate, Source PR not open, a fix that exists already. Each skip is in the report.
3Group the ticketsOne High PR for each High ticket. One Shared PR for Low and Medium tickets, at most 10 fixes.
4Fix each ticketCheck out the Source PR branch. The model reads and edits files with five tools. It tries the cheap model, then the strong model.
5Check the resultNo secret in the change. The diff is small. No change in .github/workflows/. The token ceiling holds.
6PublishCommit, push the branch gozu/fix-…, and open a draft PR into the Source PR branch.
7Update the ticketAdd a comment with the PR link. Move the ticket to review.

What veil writes

Draft Fix PROne commit for each fix. The PR has the issue- label.
Jira comment and statusThe comment holds the PR link and a short reason.
Failed FixNo safe fix. The ticket stays open with a comment and the label veil-failed-fix. No PR.
Left for the next runThe token ceiling or an expired token stopped the run. The ticket stays unchanged.
Run reportPRs, the outcome of each ticket, skipped tickets, tokens used.
Never mergesA person merges. Every PR is a draft.
Never touches the default branchIt works on the Source PR branch and its own fix branch.
No shell, no network for the modelThe model has five tools. All of them stay inside the checkout.
Ticket text is dataThe model never follows instructions in a ticket or a file.

The Engine is one entry point, run(context). It uses three parts that a Shell passes in: the tracker (Jira), the repo provider (GitHub) and the model client (OpenAI). Today the only Shell is the GitHub Action.
