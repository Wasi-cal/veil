Step 2 of 6 · Find tickets

Find the tickets veil may fix

veil skips a ticket if:

  • the ticket is on a Fix branch
  • the ticket has the label veil-failed-fix
  • the ticket has no issue-… label
  • the ticket copies an earlier ticket
  • the Source PR is closed
  • a Fix PR is open
  • a closed Fix PR left a branch

A second run does not repeat work.

Step 4 of 6 · Fix

The AI model works in a loop

  1. The Engine sends the ticket and 20 lines of code on each side of the flagged line.
  2. The model asks for a tool. It can read more of the repo this way.
  3. The Engine runs the tool and sends the result.
  4. These steps repeat, up to 25 times.
  5. The model calls finish.

The model has no shell and no web access. It can use only these five tools.

Step 4 of 6 · Fix

What the tool check looks at

read_file

The path is inside the repo. The file is not secret-like, such as .env, a key or .git.

search and list_dir

They see only files that pass the read check. Search returns at most 50 matches.

edit_file

The path is not .github/workflows or a lockfile. The file exists. The old text is in the file. The edit does not empty the file. The change stays within 200 lines.

What these checks do not do

They keep the model inside the clone. They stop leaks and edits to protected files. They do not judge if the fix is right.

Who checks the fix

A person reviews every Fix PR. Your tests run on it.
