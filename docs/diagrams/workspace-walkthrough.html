The workspace, step by step

veil never edits your branch. It edits a private clone, checks every change, and saves the result as a commit. This page shows how, in five pictures.

One group can hold several tickets (tickets of the same file). They share one clone. Each ticket gets a new WorkingCopy. A failed ticket is undone with discard_changes before the next ticket starts.

4Old and new: what the memory holds

You may have heard that edit() returns the old and the new lines. It does not. edit() returns nothing. It takes old and new from the model. It stores two things for each edited file: the text before the first edit, and the text now. Three checks use that pair.

before: stored on the first edit of the file

now: the latest text, after edit_file("app.py", "eval(input())", "int(input())")

Diff limitchanged_lines(originals, currents) compares the pair line by line. It runs at every edit and again at the end.
here: 1 changed line, limit 200
Parse checkcheck_parses(current) parses the latest text of each .py, .json and .toml file. It only parses, it never runs code.
here: ast.parse passes
Secret scanedits() hands the pair to find_new_secret(before, after). A secret counts only if the new text holds more of it than the old text.
here: no secret, the Fix goes on
Two edits to one file? The memory keeps the first text as "before" and updates "now" each time. So the pair always compares the start of the attempt with the present. A new attempt starts with empty memory, after discard_changes reset the files.

5The three states of a file

A file in the clone is always in one of these states. Only committed work can leave the runner.

adapters/github/workspace.py:61 commit adapters/github/workspace.py:70 push engine/fix/escalation.py:14

When a ticket fails, or reaches its token cap, the Engine calls discard_changes. The files go back to the last commit. A Fix that already passed stays committed. A git push sends only the branch gozu/fix-…. It never forces the push.
